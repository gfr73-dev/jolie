I want to build a Flask application from scratch.

CONTEXT:
- This replaces an IBM Notes application
- It manages "Printer installation Requests"

DATABASE is named JOLIE:
- Table register_request which holds all fields from lookup (all read-only) + the all other fields defined in the synopsis extracted from IBM Notes application
- Table installation_types, which holds: installation_type, printer_type, printer_initial_status, requires_validation (boolean)
- Table register_users which holds: username (email) password, user_dir_reg, is_admin (boolean) and is_dir_reg (boolean)
- Table register_it_tech which holds: Tech User Name (First Last), Tech user email 
- Table install_status which holds: id, status

BUSINESS RULES:
- User enters account number (fixed width 8char, only numeric:
	> If it doesn´t match this mask, no query should be submitted to AS400) → lookup from AS400
	> if the account number already exists on the register_request table, do not allow to proceed, and send a pop-up message: "Conta já instalada" 
- Form is pre-filled with lookup data (read-only fields)
- User then selects:
    - install type
    - account manager
    - IT tech responsible for installation from drop-list indexed to table register_it_tech
- initial request status derives from installation_types.printer_initial_status based on the printer_type selected.
all subsequent statuses are defined via droplist, from table request_status, only allowed to whoever is is_admin:true

- initial requires_printer_validation derives from installation_types.requires_validation based on the printer_type selected
- create different views, based on the request status field
- on save request, if account already exists in the database, display a warning and do not try to submit the info to avoid mysql erros on screen about index violations
- if printer type requires validation (requires_validation:true)
    1. send email to associated user's user_dir_reg
    2. request should appear in a sepate view, "Aguarda Validação Impressora".
Everyone can access this view, but only who is_admin:true or is_dir_reg:true can change the is_printer_validated field.

Users must be able to "view" the record, select drop list to "validated" (impressora validada) or "not validated" (impressora não validada), and click "save"
    1. validated -> sends email to the IT tech
    2. not validated -> sends email to IT tech and account_manager

TECH STACK:
- Flask
- SQLAlchemy
- MySQL
- Jinja templates
- Bootstrap UI


OUTPUT EXPECTED:
- Full project structure
- All files complete (no snippets), zip file, if possible saved on my Onedrive
- Copy-paste ready
- No broken dependencies
- landing page is the list of all requests, with option to filter by status
